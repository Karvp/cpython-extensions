# Security Policy

## Supported versions

Security fixes target the latest production release on the current CPython 3.13 line. Older historical checkpoints are retained as evidence, not as independently supported branches.

| Version | Security support |
|---|---|
| 1.0.x latest | Yes |
| older 1.0.x | Upgrade first |
| 0.x | No |

## Reporting a vulnerability

For a GitHub-hosted repository, prefer GitHub's **private vulnerability reporting** / Security Advisory flow when enabled. Please avoid publishing exploit details in a public issue before maintainers have had an opportunity to triage them.

Useful reports include:

- CPython patch version and operating system;
- minimal reproducer;
- whether the issue affects `switch`, `inline`, `goto`, or composition;
- selected mode/backend options;
- verifier result and transformation report when available;
- whether the issue can crash the interpreter, escape a documented control-flow boundary, corrupt state, or bypass a safety/validation check.

## Scope

Security-relevant findings include malformed generated bytecode, verifier inconsistencies, unsafe exception-region jumps, mutation races that violate promised semantics, memory-safety symptoms, and behavior that crosses the documented safe/unsafe backend boundary.

The explicit live switch backends and `enable_goto(mode="unsafe")` are low-level opt-in facilities. Their documented hazards are not vulnerabilities by themselves, but behavior outside their documented boundary should still be reported.

## Secrets

This project does not require runtime credentials. Never add PyPI tokens, GitHub tokens, private keys, or other secrets to the repository. The included release workflow is designed for PyPI Trusted Publishing (OIDC) when enabled.
