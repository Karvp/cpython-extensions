cpython-extensions 1.0.3 public release audit
Date: 2026-08-21

Release intent
==============
Prepare the first public cpython-extensions release for direct GitHub hosting and
PyPI publication with clean source layout, reproducible artifacts, conservative
runtime defaults, and no generated package metadata, build-host paths, or
repository secrets.

Public release state
====================
Version 1.0.3 is the only published release represented by the repository
documentation. Numeric labels retained in benchmark filenames/results describe
pre-public development comparisons and are not GitHub/PyPI release history.

Repository contents
===================
- package README and comprehensive usage guide
- architecture, compatibility, release, GitHub setup, contribution, security,
  code-of-conduct, citation, and repository metadata documents
- structured issue/PR templates
- Dependabot configuration
- GitHub workflows for CI, stress, CodeQL, dependency review, and release
- repository hygiene/version checks
- exact-artifact smoke tests
- application-style and adversarial stress harnesses
- benchmark scripts/results isolated under benchmarks/

Release safety
==============
The release workflow grants read-only contents permission by default. GitHub
Release creation receives contents:write only in its dedicated job. PyPI
publication receives id-token:write only in its dedicated job, is disabled
unless repository variable PYPI_PUBLISH_ENABLED=true, and is designed for PyPI
Trusted Publishing. Build machinery is isolated from the publishing job.

Repository hygiene
==================
Historical benchmark launchers do not use build-host paths as active defaults.
Baseline sources for comparison drivers must be supplied explicitly. Generated
caches/build metadata and common credential patterns are rejected by the
repository hygiene checker.

Validation
==========
370/370 ordinary tests passed.
370/370 CPython dev-mode warnings-as-errors tests passed.
370/370 allocator-debug + dev-mode warnings-as-errors tests passed.
81% branch-aware package coverage passed the configured 80% minimum.
19,241,648 full-scale stress operations passed.
1,167 generated code objects were independently verified in the deep harness.

Conclusion
==========
The repository is suitable for direct public GitHub publication and the 1.0.3
GitHub/PyPI release.
