python_extensions 0.18.4 — pyswitch exact-type partition certification
======================================================================

Release focus
-------------
Portable typed-switch dispatch no longer allocates `(type(subject), subject)` on every dispatch when the compiler proves that every case key in a plan has one safe exact runtime type (ordinary `type` metaclass). Matching subjects use the raw per-type dictionary. Exact-type mismatches preserve observable hash semantics by invoking the subject's real hash once, then take the miss/default path without equality or tuple allocation. Mixed-type plans and custom-metaclass case types retain the conservative tuple-key backend.

Release guarantees / conservative boundaries
--------------------------------------------
- The optimization is proof-based, not profile- or benchmark-specific.
- All case keys in the plan must share one exact runtime type.
- The case type object must use the ordinary `type` metaclass.
- Matching subjects still use ordinary Python dictionary hash/equality semantics.
- Exact-type mismatch never performs equality because typed equality is impossible,
  but the real subject hash is executed once so user hash failures remain observable.
- Intrinsically unhashable mismatches are ordinary misses/defaults.
- Mixed typed plans remain on the 0.18.3 tuple-key route.
- `auto` remains portable/non-self-modifying; raw live modes remain explicit opt-ins.
- Partition counts are exposed via `__pyswitch_typed_partition_plan_count__`,
  `__pyswitch_typed_partition_type_count__`, and optimization reports.
