python_extensions / pyswitch 0.18.2 certification
================================================

Release scope
-------------
This patch release hardens the CPython 3.13 pyswitch implementation while
keeping the ordinary @enable_switch / mode="auto" portable backend as the
production/general-purpose contract. Raw live-bytecode modes remain explicit,
experimental opt-ins.

Runtime used for certification
------------------------------
CPython 3.13.5

Implemented / refined in 0.18.2
-------------------------------
1. Stack-resident template payloads
   - Branchless portable expression templates and straight-line statement
     templates can keep selected literal payloads on the CPython operand stack
     instead of private __pyswitch_payload_* fast locals.
   - Multi-payload shapes are supported (for example x * K + C).
   - Former payload-local loads are rewritten to depth-correct COPY operations,
     including CPython 3.13 fused fast-local load forms.
   - Multi-payload returns preserve CPython 3.13's empty-stack-at-RETURN_VALUE
     invariant with one deep SWAP followed by N POP_TOP cleanup operations.
   - The transform fails closed outside CPython 3.13 and for unsupported
     branching, suspension, exception/control-flow, or bytecode layouts.

2. Conservative statement-template contract
   - Shared statement-template lowering is restricted to truly straight-line
     statements.
   - try/loop/nested-control-flow shapes conservatively use balanced lowering.

3. Debugger / tracer / line-table hardening
   - Generated locations that fall before a function's physical first source
     line are normalized after compilation.
   - Explicit live wrappers are relocated into the original function's source
     range.
   - Portable and live regression tests cover sys.settrace, sys.setprofile and
     CPython sys.monitoring paths.
   - Remaining documented caveat: several portable O(1) routes can deliberately
     share one canonical compiled template body, so exact per-route case-body
     line attribution is not guaranteed within that shared region. Generated
     source locations nevertheless do not escape before the real function range.

4. Live-mode semantics / hot-path recovery
   - Python-key and exact-type live dispatch now treat subjects with
     __hash__ = None as ordinary misses/defaults, matching portable semantics.
   - TypeError genuinely raised by user __hash__/__eq__ still propagates.
   - The subject is evaluated exactly once.
   - Common lookup remains bound C-level dict.get; CPython zero-cost exception
     handling covers only the exceptional intrinsically-unhashable path.
   - Compiler subject/gate temporaries are deleted before selected user code.

Interpretation
--------------
The production portable direct-table path remains direct-dict-class speed and
essentially flat with case count. Stack-resident expression/statement templates trade roughly 1-3% throughput in
this reproduced run for eliminating common payload fast-locals from observable
frames. The direct portable path remains direct-dict-class speed. Exact-type live
dispatch improves materially. The experimental untyped live path intentionally
pays about 8.7% for corrected single-evaluation/unhashable semantics rather than
weakening behavior. One typed-portable sample set was noisy; the reported median
therefore should not be interpreted as an architectural regression without a
longer dedicated benchmark.

Release recommendation
----------------------
Use @enable_switch / mode="auto" without live_threshold for general production
code. Treat fast/thread_local/isolated/per_call as CPython-3.13-specific explicit
research/compatibility modes.
