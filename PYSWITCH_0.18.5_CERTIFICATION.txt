python_extensions / pyswitch 0.18.5 certification
=================================================

Environment
-----------
Python: CPython 3.13.5
Release: python_extensions 0.18.5
Focus: production portable pyswitch multi-type allocation-free exact-type routing

Design certified
----------------
0.18.5 extends the allocation-free typed fast path introduced in 0.18.4 from
single-type case plans to safe multi-type plans.

For case_key_mode="typed":

* A single safe exact case type retains the 0.18.4 `type(subject) is T` path.
* A safe multi-type plan creates one ordinary subject dictionary per exact type
  and a type-object router whose values are the corresponding bound dict.get
  callables.
* Runtime multi-type dispatch performs one `type(subject)` router lookup and one
  ordinary subject-table lookup. It does not allocate `(type(subject), subject)`
  on the optimized route, create a Python helper frame, or create a generated
  routing local.
* Exact-type subject dictionaries preserve ordinary Python hash/equality
  semantics, collisions, and user exceptions within each exact type.
* Subject equality cannot cross exact-type partitions.
* If any case-key type object uses a custom metaclass, the complete typed plan
  remains on the historical tuple-key backend.
* An unknown runtime type takes the router miss getter, which still performs the
  subject's real hash operation; intrinsic unhashables remain normal switch
  misses while genuine user hash failures propagate.
* The existing stack-resident expression/statement payload lowering remains
  active and frame-transparent on supported CPython 3.13 shapes.
* Production `auto` remains portable/non-self-modifying. Raw live bytecode modes
  remain explicit experimental opt-ins.

Unknown-type miss timing is more sensitive to process/CPU noise than the hit
paths. A separate interleaved 13-process check with 700,000 calls per child for
the 4-type unknown miss measured 89.590 ns for 0.18.4 and 87.970 ns for 0.18.5
(1.018x). Therefore the release does not claim a guaranteed miss speedup; the
headline result is the consistent removal of tuple-allocation overhead on
multi-type typed hits and template/guarded routes.

Interpretation
--------------
The optimized mixed typed path is generally 1.10-1.13x faster for 2/4/8-type
direct-hit workloads in the final benchmark, while expression and statement
templates improve about 1.06x and guarded balanced typed routing about 1.02x.
The unchanged single-type path remains near parity/slightly positive. Absolute
nanosecond timings are machine/build dependent; semantic/differential gates are
the authoritative certification criteria.
