Implemented in 0.18.3
---------------------
* Depth-aware last-use scheduling for CPython 3.13 stack-resident template payloads.
* Final payload reads at physical depth 1 are consumed with no load opcode.
* Final payload reads at depth 2 use SWAP 2 instead of COPY + later cleanup.
* A sole return carrier at depth 3 may use SWAP 2; SWAP 3 because removing the
  terminal SWAP/POP pair still gives a strict instruction-count win.
* Deeper payload carriers remain on COPY lowering when rotations are not a clear win.
* Fused LOAD_FAST_LOAD_FAST payload components participate in the same scheduler.
* Structurally identical templates discard their unused identity payload once at
  the join while preserving the dictionary lookup and therefore hash/equality effects.
* No payload fast locals are reintroduced.

Correctness/production invariants retained
------------------------------------------
* Python dictionary hash/equality semantics in case_key_mode="python".
* Exact runtime type participates in case identity in case_key_mode="typed".
* Intrinsically unhashable subjects are misses/defaults; user hash/equality
  TypeError exceptions propagate.
* Subject expressions are evaluated once.
* No compiler payload fast locals are visible in stackified template user code.
* CPython 3.13 RETURN_VALUE receives an empty operand stack after the result is popped.
* Tracing/sys.monitoring line locations stay within valid source ranges.
* Unsupported runtimes/shapes fail closed to the proven portable fallback.
* mode="auto" does not mutate executable bytecode.
